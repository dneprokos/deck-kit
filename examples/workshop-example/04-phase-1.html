🕸️ Phase 1 · Pin

Pin current behaviour

Before you touch a line, capture what the code does today in tests you can trust.
You + AI 20 min
Goal
Wrap the untested module in a characterization suite that records its real output — so any later change that moves behaviour turns the bar red.
Input
🍝
Legacy module
Working code, no tests. Behaviour lives only in the reader's head.
Output
🕸️
Green characterization suite
Every public path pinned to its observed result.
Commands
$ npm test -- --watch
Keep the suite running while you add each pinning test.
$ git commit -m "pin behaviour"
Lock in the safety net as its own commit before refactoring.
Gate
Behaviour pinned
  • Every public path has a test
  • Expected values are recorded, not guessed
  • Suite is green
  • No production code changed yet
◆
Pattern · Pin, don't fix
If the code returns something that looks wrong, record it anyway. A characterization test asserts what is; correcting behaviour is a later, separately-tested change.
