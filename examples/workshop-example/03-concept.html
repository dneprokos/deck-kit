The Refactoring Safety Net

Refactoring is safe only when three things hold at once. Drop any one and you are just editing code and hoping.

🕸️
Net · 01
Characterization tests
Tests that pin what the code actually does today — bugs and all — before you touch it. They describe behaviour, not intent.
Catches: silent behaviour drift
👣
Net · 02
Small steps
One structural move at a time — rename, extract, inline — each small enough that if it breaks, you know exactly which step did it.
Catches: hard-to-locate regressions
✅
Net · 03
Continuous green
Run the suite after every step. The bar never leaves green for more than a moment, so you always have a safe point to return to.
Catches: a broken commit reaching main
