# Talk: Small Pull Requests Win

A 15-minute conference talk. One thesis, one memorable line, one ask.

[HOOK] What if the single highest-leverage engineering habit costs
nothing, needs no tooling, and you could start tomorrow? It fits in one
sentence: make your pull requests smaller.

[THESIS] Review quality is inversely proportional to diff size. A 100-line
PR gets 10 comments; a 1000-line PR gets "LGTM". The reviewer's attention
is the scarce resource, and diff size is how you spend it.

[STORY] Industry review guidelines converge on the same number from
different directions: several hundred lines per review session is where
defect-detection effectiveness drops off a cliff. Beyond that, reviewers
stop reading and start skimming.

[MEMORABLE] A big PR is not a unit of work. It is a unit of risk.

[CTA] For one week, cap every PR you open at 200 lines. Measure your
review turnaround before and after. Then decide for yourself.
